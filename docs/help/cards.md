# 卡片类型

Anywhere- 当前定义了 11 种卡片，其中 9 种可以从主界面的“添加卡片”入口直接创建。卡片类型决定编辑字段、执行方式和所需权限。

## 类型总览

| 类型 | 主要用途 | 通常需要的权限 |
| --- | --- | --- |
| URL Scheme | 打开 URL、App Scheme 或 Intent URI | 无 |
| Activity | 启动指定包名和 Activity | 无；不可导出 Activity 可能需要 Root/Shizuku |
| Mini Program | 以小程序参数创建卡片 | 取决于实际生成的配置 |
| QR Code | 打开内置扫码合集或二维码动作 | 部分动作需要 Root 或无障碍 |
| Image | 显示本地或网络图片 | 无 |
| Shell | 执行一条 Shell 命令 | Root 或 Shizuku |
| Switch Shell | 用开/关两条命令切换状态 | Root 或 Shizuku |
| File | 用系统应用打开文件 URI | 无 |
| Broadcast | 发送 Android 广播 | 通常无；受限广播可能需要更高权限 |
| Workflow | 按顺序执行多张卡片 | 取决于每一步 |
| Accessibility | 通过无障碍节点自动操作目标 App | 无障碍服务 |

“Mini Program”和“QR Code”出现在类型定义中，但“添加卡片”界面不提供它们：Mini Program 没有独立编辑器，QR Code 主要从扫码合集或导入配置产生。其余 9 种可从“添加卡片”直接创建。

## URL Scheme

用于打开标准 URL Scheme、网页链接或 Android Intent URI。

主要字段：

- **App 名称**：卡片标题，必填。
- **URL Scheme**：必填。支持 `https://...`、`scheme://...` 和 `#Intent;...` 字符串。
- **动态参数**：可选。每次打开前弹窗输入，输入内容会追加到 URL 后面。
- **描述**：可选。

保存时，应用会尝试从 URL Scheme 推断目标包名，以便在目标 App 被冻结时先解冻。URL Scheme 编辑器支持“使用 root 执行”；启用后，动作会走命令执行路径。

常见示例：

```text
https://example.com
weixin://
alipayqr://platformapi/startapp?saId=10000007
```

没有 App 能响应 URL 时会提示“没有 App 可以响应此 URL”。动态参数会直接拼接在原 URL 后，填写时注意不要重复添加分隔符。

## Activity

直接启动指定 App 的 Activity。

主要字段：

- **App 名称**：必填。
- **包名**：目标 App 包名。
- **类名**：目标 Activity；留空时尝试打开目标 App 的启动 Activity。
- **Intent Action**：可选，默认按 `android.intent.action.VIEW` 处理。
- **Intent Data**：可选 URI。
- **Intent Extras**：可添加 String、Bool、Int、Long、Float、Double、Uri 类型参数。
- **描述**：可选。

如果包名和 Action 都为空，保存会失败。若类名以 `.` 开头，会自动补全为 `包名 + 类名`。

不可导出的 Activity 不能通过普通 `startActivity` 打开，应用会改为执行 `am start` 命令，因此需要 Root 或 Shizuku。编辑器中的“使用 root 执行”可以强制走命令路径。

Extras 的键和值都为空时会被忽略。数值类型转换失败时，该参数不会写入 Intent。

## Mini Program

类型定义中保留 Mini Program（类型值 `2`），用于表示小程序类卡片。当前版本没有独立编辑器，也没有出现在“添加卡片”界面；普通用户主要通过云端规则、分享卡片或导入配置创建。执行效果取决于卡片中保存的包名、参数和 Intent 配置。

## QR Code

表示扫码或付款码类动作。普通编辑器只允许修改名称和描述，动作本身来自内置扫码合集或导入的卡片。

内置扫码合集包含微信、支付宝、QQ、云闪付等入口。部分入口直接打开 App，部分需要 Root，微信收款码的无障碍版本还需要无障碍服务。

从扫码合集长按可把内置卡片加入主页。内置动作依赖第三方 App 的私有 Scheme、Activity 或界面文本，App 更新后可能失效。

## Image

显示一张本地或网络图片。

主要字段：

- **App 名称**：必填。
- **图片 URI**：本地文件通过系统文件选择器获取，网络图片可填写 `http://` 或 `https://` URI。
- **描述**：可选。
- **展示图片时亮屏**：打开图片时临时把屏幕亮度调到最高，关闭后恢复。

图片卡片没有“测试”按钮。它不会包含在备份中，因为本地 URI 权限通常无法迁移到另一台设备。

## Shell

执行一条 Shell 命令，并显示结果对话框。

主要字段：

- **Shell 名称**：必填。
- **命令内容**：必填，填写完整命令。
- **描述**：可选。
- **使用 root 执行**：启用后通过 Root 执行。

实际执行通道由工作模式决定：

- URL Scheme 模式：不能执行 Shell，通常提示切换工作模式。
- Root 模式：通过 Root Shell 执行。
- Shizuku 模式：通过 Shizuku 执行。

命令失败或返回空结果时会显示空内容或错误提示。执行前确认命令不会删除数据、修改系统关键配置或影响其他应用。

## Switch Shell

用一组开/关命令实现可切换状态，例如打开或关闭某个系统开关。

主要字段：

- **名称**：必填。
- **开指令**：必填，当前状态为关时执行。
- **关指令**：必填，当前状态为开时执行。
- **描述**：可选。

卡片状态显示在编辑器中。点击卡片后执行对应命令，并翻转状态；如果卡片已加入动态 Shortcuts，图标上的红/绿状态点也会更新。

Switch Shell 编辑器没有“测试”按钮，且不能直接分享。

## File

用系统文件选择器保存一个文件 URI，点击卡片时通过 `ACTION_VIEW` 打开。

- **文件 URI**：必填，通过“选择文件”获取。
- **App 名称**：必填。
- **描述**：可选。

文件卡片没有测试按钮，也不会包含在备份中。换机或清理文件提供者后，旧 URI 可能失效。

## Broadcast

发送 Android 广播。

主要字段：

- **App 名称**：必填。
- **Intent Action**：为空时使用 `com.absinthe.anywhere_.BROADCAST`。
- **包名**：可选，限制广播目标。
- **类名**：可选，指定广播接收器类名；填写类名时通常也要填写包名。
- **Intent Data**：可选 URI。
- **Extras**：支持 String、Bool、Int、Long、Float、Double、Uri。
- **描述**：可选。

Android 对隐式广播和后台广播有限制。即使配置正确，目标 App 也可能因为版本、权限或系统限制收不到广播。

## Workflow

按顺序执行多张卡片。

主要字段：

- **App 名称**：必填。
- **描述**：可选。
- **Flow 节点**：每个节点包含一张卡片和延时时间。

添加节点时可以新建卡片或从已有卡片中选择；节点可以拖动排序。执行时应用会启动前台服务，按顺序调用每张卡片，并在节点之间等待设置的延时。

Workflow 的权限取决于每个节点。例如包含 Shell 节点就需要 Root/Shizuku，包含无障碍节点就需要无障碍服务。首次执行 Workflow 时会显示无障碍声明，即使当前流程没有无障碍节点。

节点中的卡片修改后，Workflow 保存的是当时选择的配置；需要重新选择才能同步后续修改。

## Accessibility

通过无障碍服务打开目标 App，并按预设步骤点击文本、View ID 或坐标。

主要字段：

- **App 名称**：必填。
- **启动的应用**：目标包名。
- **入场 Activity**：目标启动 Activity。
- **无障碍节点**：点击/长按文本、点击/长按 View ID、点击/长按坐标。
- **描述**：可选。

每个节点可以设置：

- 内容：文本、View ID 或 `x,y` 坐标。
- 内容所在 Activity：留空表示沿用上一步的 Activity。
- 延时：等待该页面出现后再执行动作的额外等待时间。
- “包含”：文本匹配从完全相等改为包含匹配；多个候选文本可用 `|` 分隔。

执行前应用会等待目标页面出现。等待超时、控件不存在或坐标变化都会让步骤失败。

无障碍功能依赖目标 App 的界面结构，更新后可能失效；不要把来源不明的无障碍卡片用于敏感应用。
