# 常见问题

## 安装后无法启动或一打开就退出

先区分是安装问题、签名问题还是应用崩溃：

1. 确认安装的是本 fork 的 Release APK，而不是 debug、unsigned 或旧签名的包。
2. 如果从其他签名的 Anywhere- 覆盖安装，系统可能拒绝；不要直接卸载后才发现没有备份。
3. 连接 ADB 抓取崩溃日志：

   ```bash
   adb logcat -d | grep -E 'AndroidRuntime|FATAL EXCEPTION|com.absinthe.anywhere_'
   ```

4. 确认设备架构是 ARM；本项目不包含 x86/x86_64 原生库。

如果是某个版本升级后启动崩溃，保留原 APK 和日志，回退到上一个可用版本，并报告崩溃堆栈。

## 提示“应用未安装”

通常是同包名但签名不同。Android 不允许用不同证书覆盖安装同一个应用：

- 上游 Anywhere-、本 fork Release、debug 版本之间通常不能互相覆盖。
- 需要保留数据时先备份，再卸载旧版本并安装新版本。
- 安装后确认包名是 `com.absinthe.anywhere_`，不是 `.debug`。

不要用重新签名的方式绕过，否则后续更新仍会失败。

## 桌面快捷方式没有出现

依次检查：

1. 是否在卡片编辑器中选择了“添加桌面快捷方式”，而不是只加入动态 Shortcuts。
2. 是否在启动器弹窗中确认。
3. 启动器是否支持 pinned shortcut；部分第三方桌面不支持。
4. 是否只看到“已请求创建”而没有“已创建”；后者才表示系统回调成功。

可用 ADB 检查系统记录：

```bash
adb shell dumpsys shortcut | grep -C 4 'pinned_'
```

应看到 `pinned_<entityId>`。如果记录存在但桌面没有图标，问题在启动器而不是卡片 ID。

## “清除 Shortcuts”后桌面图标还在

这是预期行为。设置中的“清除 Shortcuts”只清除动态 Shortcuts，不删除桌面固定快捷方式。桌面图标需要在桌面或启动器中单独移除。

## URL Scheme 卡片没有反应

- 确认 URL 能被浏览器或目标 App 识别。
- 确认目标 App 已安装且未被冻结。
- 检查是否有动态参数等待输入。
- 尝试在浏览器中直接打开同一 URL Scheme。
- 如果提示“没有 App 可以响应此 URL”，说明系统中没有应用注册该 Scheme。

网页 URL 打开到浏览器是正常结果。动态参数会直接拼接到 URL 后面，注意 `?`、`&` 等分隔符不要重复。

## Activity 卡片提示 Activity 被阻止访问

目标 Activity 可能没有导出。普通应用不能直接启动未导出的 Activity，Anywhere- 会尝试用 Root/Shizuku 执行 `am start`。请切换工作模式并授予对应权限，或改用 URL Scheme。

## Shell 卡片提示切换工作模式

Shell 不能在 URL Scheme 模式下执行。切换到 Root 或 Shizuku 模式，并确认：

- Root 已授权；或 Shizuku 正在运行且已授权。
- 命令本身存在且语法正确。
- 命令不依赖当前未提供的环境变量或工作目录。

## Collector 打不开

Collector 只在 Root 或 Shizuku 模式下工作，并且需要悬浮窗权限。MIUI 还可能需要“后台弹出界面”权限。权限授予后，先回到主页再启动 Collector。

## 无障碍卡片没有点击

- 在系统设置中确认 Anywhere- 的无障碍服务已开启。
- 确认目标 App 的包名和 Activity 正确。
- 检查文本、View ID 或坐标是否仍匹配当前界面。
- 增加节点延时，等待目标页面完全加载。
- 目标 App 更新后控件结构可能变化，需要重新配置卡片。

无障碍服务被系统关闭、应用被强行停止或目标 App 使用安全窗口时，自动操作可能失败。

## 打开冻结的 App 提示选择解冻模式

在 **设置 → 解冻模式** 中选择并配置可用方式。Root/Shizuku、DPM、DSM 和 IceBox SDK 的可用性取决于设备和已安装应用。配置错误时会提示未选择解冻模式或解冻失败。

## 备份提示格式错误

- 确认文件是 `.awbackups`，不是普通 JSON 或文本。
- 确认文件没有被截断、重命名或二次编辑。
- 确认使用的是同一 fork 的兼容版本。
- 旧版本结构可能不兼容当前版本，尝试用生成该备份的版本恢复。

恢复前先保留原始文件副本，不要覆盖原备份。

## 恢复后出现重复卡片

恢复会追加数据，不会先清空数据库。重复恢复同一份文件会产生重复项。删除重复卡片前先备份当前状态，避免误删。

## 图片或文件卡片没有备份

这是设计限制。图片和文件卡片依赖本地 URI 和文件访问权限，备份会跳过它们，并清空自定义图标 URI。请在换机后重新选择文件或图片。

## 从其他 Anywhere- 版本升级后数据不见了

覆盖安装通常保留数据；卸载会删除应用数据。确认是否发生过以下情况：

- 因签名不兼容而卸载重装。
- 在 debug 版和 Release 版之间切换（包名不同）。
- 从不同 fork 安装。
- 恢复了旧结构备份。

以后确认签名一致后，始终覆盖更新，不要卸载。

## 如何反馈问题

提供以下信息，能显著减少排查时间：

- Anywhere- 版本名和 versionCode。
- 设备型号、Android 版本、ROM 类型。
- 工作模式和解冻模式。
- 复现步骤。
- 相关卡片的类型和非敏感配置。
- `adb logcat` 中的崩溃堆栈或错误日志。

不要在公开 Issue 中粘贴包含账号、Cookie、内部地址或 Shell 密钥的完整配置。
